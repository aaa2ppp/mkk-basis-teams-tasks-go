# Cервис для управления задачами внутри команд с ролевой моделью, историей изменений, кешированием списка задач и SQL отчетом (GO)

[Техническое задание](./docs/TS.md)

## Быстрый старт

### Клонирование репозитория

```bash
git clone https://github.com/aaa2ppp/mkk-basis-teams-tasks-go.git
cd stackbridge-it-teams-tasks-go
```

### Переменные окружения

Пример всех используемых переменных окружения находится в файле [`dot.env.example`](./dot.env.example).  
Скопируйте его и отредактируйте под свои нужды:

```bash
cp dot.env.example .env

# Сгенерировать случайные пароли для базы данных и кеша
echo -e "\nDB_ROOT_PASSWORD=$(head -c16 /dev/urandom | base64 | tr '+/' '-_' | tr -d '=')"  >> .env
echo -e "\nDB_PASSWORD=$(head -c16 /dev/urandom | base64 | tr '+/' '-_' | tr -d '=')" >> .env
echo -e "\nREDIS_PASSWORD=$(head -c16 /dev/urandom | base64 | tr '+/' '-_' | tr -d '=')"  >> .env

# Сгенерировать секрет для генерации токенов
echo -e "\nAUTH_SECRET=$(head -c32 /dev/urandom | od -An -v -tx1 | tr -d ' \n')" >> .env
```

### Локальный запуск

```sh
# Загрузить переменные окружения
source dev-env

# Создать/обновить go.work (требуется для интеграционных тестов)
make init-workspace

# Установить зависимости и проверить утилиты (при необходимости будут установлены)
make deps check-tools

# Запустить приложение
make run
```

### Запуск в Docker

```sh
# Запустить приложение в контейнере
make docker-run
```

## Интеграционные тесты

Интеграционные тесты вынесены в отдельный модуль `./tests`, чтобы тяжёлые зависимости (testcontainers, goose и др.) не попадали в основную сборку.

Для их локального запуска необходимо предварительно инициализировать Go workspace:

```bash
make init-workspace
make test-integration
```

## Ограничения, особенности и отступления от ТЗ

### Оговорки по работе с комментариями

В текущей реализации комментарии могут оставлять **все участники, имеющие права на редактирование задачи** (создатель команды, администратор команды, создатель задачи и исполнитель).

> Формально это противоречит ТЗ (только исполнитель может оставлять комментарии).

Комментарий рассматривается как **вспомогательный инструмент для уточнений и оперативного общения** по ходу выполнения задачи. 

**Важно:** 
- Комментарии **не записываются** в историю изменений задачи.
- **Статус, исполнитель, описание и название задачи** считаются единственными источниками истины.
- Если в комментариях было принято решение изменить какой-либо атрибут задачи, это решение **должно быть зафиксировано** путём явного изменения соответствующего поля задачи.


### Особенности авторизации

В системе используется JWT-токен, содержащий информацию о командах и ролях пользователя. Это позволяет выполнять **быструю предварительную проверку** прав доступа без обращения к базе данных, что положительно сказывается на производительности.

Однако следует учитывать, что при изменении состава команды или роли пользователя (добавление/удаление из команды, повышение/понижение роли) ранее выданный токен **не обновляется автоматически**. В связи с этим данные в токене могут устаревать.

Для обновления информации в токене пользователю необходимо выполнить повторный вход в систему.

Несмотря на предварительную проверку, каждый запрос, требующий прав доступа, **всегда выполняет финальную проверку актуальных прав пользователя на основе данных из базы**. Это гарантирует, что критически важные действия совершаются только при наличии реальных полномочий, независимо от содержимого токена.
